## 这是什么

麦当劳的限定周边、联名玩具、季节新品，热度一起来，**总有些门店先卖光**。

- App 里看到的是"当前已售罄"，但**不知道别的哪家店还有货**；
- 只能一家一家切门店、翻菜单、对名字，翻到第 5 家已经不想去了；
- 好不容易放弃，过两天刷到别人晒单——**它悄悄返场了，而你完全不知道**。

**麦麦限定黄金眼**用一个 Skill 把这两件事收进同一条链路：

| 能力 | 一句话 |
|---|---|
| 🔍 **售罄寻货** | 说一句"泷泷星愿售罄了"，扫附近门店，直接告诉你**哪家还有货、多远、多少钱、要不要随单购**，选店即下单 |
| 🎯 **周边情报表** | 不指定商品时，自动汇总附近门店所有"限定周边/上新"商品的在售分布 |
| ⏰ **返场蹲守** | 加入蹲守清单，之后每次运行自动复查，商品**从售罄变为在售的瞬间提醒你** |

---

## 定位：补上情报链路里缺的那一段

麦当劳限定品这件事，用户实际要走完整条链路：

```
① 知道有什么要上        ← 情报层（活动日历 / 积分商城）
② 定闹钟、准点抢        ← 动作层
③ 没抢到，哪家店还有？   ← 门店层  ★ 黄金眼
④ 也卖光了，什么时候回来？← 时间层  ★ 黄金眼
```

现有工具大多做 ①②：告诉你"今天有什么能抢、你够不够格、场次约不约得上"。
但 ③④ 基本是空白——**因为官方 MCP 没有库存接口，很多项目在 README 里明确写了"不做库存、不推测"**。

黄金眼只做 ③④，且把它做到闭环：

| | 情报层工具 | 麦麦限定黄金眼 |
|---|---|---|
| 数据粒度 | 活动 / 商城 SKU | **具体门店 × 具体商品** |
| 时间性 | 一次性快照 | **状态快照 + 变化检测（蹲守）** |
| 回答的问题 | 有什么能抢 | **哪家店现在有货；什么时候重新有货** |
| 抢不到之后 | 无解 | 跨店寻货 → 直接换店下单 |

一句话：**别人解决"怎么抢得到"，黄金眼解决"抢不到怎么办"。** 而限定品售罄后的需求是真实存在的——用户不会因为门店缺货就不想要了，他只是不知道去哪儿买。

## Roadmap

- **v1.0（当前）**：售罄寻货 · 周边情报表 · 返场蹲守
- **v1.1（规划）**：接入 `campaign-calendar` 做"限定上新前置提醒"，把 ① 层补上，形成完整链路；但**开售倒计时不会造数据**——日历接口给不到精确到分钟的开售时刻就如实说明
- **v2.0（构想）**：返场热度统计（同一商品的售罄-返场周期），为用户提供"这类商品通常多久回一次"的经验区间；**门店侧**可聚合匿名化的售罄数据，辅助补货决策（需官方授权，当前仅作设想）

- **限定周边收集党**：汪苏泷联名、开心乐园玩具、联名棒球帽，一样都不想错过

## 它是怎么工作的

核心发现：**麦当劳 MCP 的 `query-meals` 按门店返回"当前可售菜单"，售罄商品会直接从列表里消失**。

```
用户："泷泷星愿四件套售罄了，附近哪家还有？"
        │
        ▼
① query-nearby-stores  取附近门店（城市+关键词）
        │
        ▼
② query-meals × N 店   逐店取菜单，检测目标商品 code 是否存在
        │  ├─ 存在 → ✅ 有货
        │  └─ 缺失 → ❌ 疑似售罄/未上架
        ▼
③ 有货门店按距离排序 → 营业时间 → 价格 → 是否随单购
        │
        ▼
④ 选定门店 → calculate-price → create-order → 支付链接
        │
        ▼
⑤ （可选）加入返场蹲守清单，下次运行自动复查状态变化
```

关于**判定可靠性**的诚实说明，见 [MCP_INTEGRATION.md](MCP_INTEGRATION.md#售罄判定的边界与置信度)。

## 快速开始

### 方式一：在 WorkBuddy 中作为 Skill 使用（推荐）

1. 申请麦当劳 MCP Token：<https://open.mcd.cn/mcp>（右上角登录 → 控制台 → 激活）
2. WorkBuddy 左侧【连接器】→【自定义连接器】→【配置MCP】，填入：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_TOKEN"
      }
    }
  }
}
```

3. 保存并启用 `mcd-mcp`
4. 把本仓库的 `SKILL.md` 作为技能加载，然后直接说：
   - 「泷泷星愿四件套售罄了，苏州园区附近哪家还有？」
   - 「帮我看看附近门店还有哪些限定周边在售」
   - 「蹲一下泷泷星愿，有货就告诉我」

### 方式二：命令行独立运行（无需 WorkBuddy）

```bash
# 1. 配置 Token（二选一）
#    a) 环境变量
set MCD_MCP_TOKEN=你的Token        # Windows
export MCD_MCP_TOKEN=你的Token     # macOS / Linux
#    b) 或复制 .env.example 为 .env 并填写
#    注：脚本也会自动读取 ~/.workbuddy/mcp.json 中已配置的 mcd-mcp Token

# 2. 售罄寻货
python scripts/golden_eye.py find --city 苏州市 --near 永旺梦乐城 --item 泷泷星愿

# 3. 周边情报表（自动抽取限定周边/上新商品）
python scripts/golden_eye.py radar --city 苏州市 --near 永旺梦乐城

# 4. 返场蹲守
python scripts/golden_eye.py watch --add --city 苏州市 --near 永旺梦乐城 --item 泷泷星愿
python scripts/golden_eye.py watch --check        # 复查全部蹲守项，有变化才提醒
python scripts/golden_eye.py watch --list
```

## 设计取舍（为什么这样做）

- **只用官方 MCP，不爬 App、不抓包**：全部数据来自麦当劳中国官方 MCP 服务，稳定且合规。
- **"缺席检测"而非"库存接口"**：官方 MCP 没有库存量接口，本项目用"门店可售菜单中是否包含该商品"作为在售/售罄信号，这是 MCP 能力范围内**最接近库存真相**的可用信号。
- **不猜"即将备货"**：没有任何接口能给出补货时间，所以项目**不给假承诺**，只回答"现在哪家有货"。
- **蹲守状态在本地产**：watchlist 存在用户本地，不上传、不联网，不涉及任何个人数据。
- **下单只是衔接，不越权**：所有交易动作都走官方 `create-order`，支付仍由用户在官方渠道完成。
